## 一、设计目标与保留边界

### 已确认

- 网站以个人审美、好看和辨识度为重要目标，允许艺术字体、手写感、非对称构图和有节奏的视觉变化。
- 避免过于板正、重复、所有内容围绕同一中轴排列的模板感。
- 用户已亲自调整前四屏，内容也经过打磨。后续设计在现有内容与表达意图上优化，不擅自改写、删减或新增人物事实、项目介绍、口号与标签。
- 保留现有四屏的主题、内容顺序和已确认的主要交互。局部位置、字形与视觉强调可以讨论，但不默认推翻整屏结构。
- 本阶段先建立字体要求，再讨论布局规范。移动端专项适配暂缓。
- 后续做移动端时，沿用“同一视觉身份，分别编排”的方向；当前不把两端重排列入实施范围。

## 二、字体要求

状态：**用户已确认，作为当前暂定方案。**

### 2.1 字体角色

| 角色 | 当前选定方向 | 使用范围 |
| --- | --- | --- |
| 主标题字 | A：手札体（Hannotate SC） | “何必”、页面标题、栏目标题、About 六条人物标题 |
| 批注字 | B：翩翩体（HanziPen SC） | 短旁注、签名、局部手写强调 |
| 阅读字 | 清楚的中文黑体，当前试样为苹方 | 人物说明、项目介绍、文章正文、按钮与操作文字 |
| 信息字 | 等宽字体，正式实现优先沿用 JetBrains Mono | 日期、编号、技术代号、英文信息标签 |

- 用户明确排除 C 圆体、D 魏碑，不再把它们作为本站艺术字候选。
- 宋体不作为本方案的主视觉字体。
- 字体试样里的信息字使用本机 Menlo 展示等宽效果；这不代表正式方案改为 Menlo。
- 英文项目名如 `Deepulse`、`AOAI` 可以保留 Space Grotesk；中英混排需要检查大小、基线与粗细是否协调。
- 既有 Logo 是独立品牌图形，不因为全站标题字体调整而自动替换。

### 2.2 使用规则

1. 同类内容使用同一角色。六条人物标题保持一致，不一条换一种字体。
2. 艺术变化主要由手札体和翩翩体承担，不继续为每个模块增加新字库。
3. 翩翩体主要用于短语或短句；完整解释段落、正文与操作说明使用阅读字。
4. 区分“有情绪的短批注”和“需要准确理解的小字说明”，不因字号小就统一改成花体。
5. 文章页的大标题可以使用主标题字；长文正文和正文内的小节标题以连续阅读清楚为优先。
6. 字体按语义角色集中定义，组件引用角色，不在每个组件里分别硬编码一套字体名称。
7. 更换字体时连同字号、行高、字距一起检查，避免沿用旧字体参数造成笔画拥挤、裁切或中英比例失衡。

### 2.3 字号与可读性起点

- 日期、编号、辅助信息：以至少 12px 为起点。
- 简短解释、人物说明、项目说明：约 14–16px。
- 长文正文：约 16–18px。
- 艺术标题：结合实际字形与内容长度试排，不在本阶段强行统一所有标题的尺寸。
- 上述数值是设计起点，不是已经完成验证的全站硬编码结果；使用真实文案检查后再落实。

### 2.4 字库与上线要求

- 以用户确认过的实际字样作为审美基准，不只按字体名称判断。
- 本机试样使用系统安装的字体；用户已确认网页分发授权，正式网页使用自托管 WOFF2，按中文字符范围加载。
- 不依赖所有访客都安装同一套 Mac 字体，也不把未加载时的系统替代字形冒充选定字体。
- 如果因授权、字形覆盖或加载条件需要替代字库，应展示对应试样后再定，不静默替换视觉风格。
- 不把“机器上能使用字体”直接等同于“可以把字体文件公开分发”。

## 三、布局与对齐规范

状态：**第二屏融合方案已确认并授权写入网站；其他页面保持当前设计，不做额外重排。**

### 3.1 已确认的方向

- 不能所有内容都居中，也不能所有区块使用相同构图。
- 可以使用左对齐、右对齐、居中，以及适量错位、层叠、边缘卡片等手法，让页面有变化。
- 各种对齐方式需要服务内容和视觉重点，不能为了变化而轮流把每段文字移向不同方向。
- 在用户现有前四屏和定稿内容的基础上优化，不把设计工作变成重写内容或重新搭一套首页。

### 3.2 需要区分的三个问题

以下作为讨论框架，不作为已批准的最终参数：

1. **内容容器的位置**：整块内容可以位于页面中部、偏左或偏右。
2. **容器内部的文字对齐**：一块放在右侧的正文仍然可以左对齐；居中的容器也不意味着文字必须居中。
3. **整屏的视觉重心**：标题、图形、卡片或产品界面中，哪一个应该先被看见，其余元素如何配合。

“避免全居中”需要检查这三层，不能只批量替换 `text-align`。

### 3.3 逐屏讨论起点

| 内容面 | 接下来需要判断的问题 | 当前不直接下结论的部分 |
| --- | --- | --- |
| Hero | 名字、介绍、Logo、索引的主次是否清楚；哪些元素共享对齐边 | 不预设整屏必须偏左或必须加入新卡片 |
| About | 标题、六条内容与图形的对应能否更清楚；如何减少重复感 | 不打散六条内容，不轮流给正文做左右对齐 |
| ProductShowcase | 产品界面是否是主角；外围标题、说明与编号能否形成层次 | 不为打破居中而移动主要产品界面或遮挡其内容 |
| ProjectsWheel | 轮盘中心与外围标题、说明是否需要不同的对齐方式 | 不为了非对称而破坏轮盘的操作和空间关系 |

### 3.4 后续讨论与验收方式

- 先看字体替换后的真实页面，再决定布局需要改到什么程度。
- 每次针对一个具体问题提出小范围修改，用相同内容展示修改前后。
- 对齐、内容密度、留白、卡片层叠和透视分别讨论，避免同时修改后无法判断是哪项产生效果。
- 判断时回答：第一眼看什么、第二眼读什么、内容关联是否清楚、是否保留原有气质。
- 视觉偏好由用户确认；涉及“通行做法”或外部案例的判断，应给出实际案例和验证范围，不凭印象宣布某种布局一定更高级。

### 3.5 第二屏已确认方案

- 连续画布，不使用六行表格或六张独立卡片包装内容。
- 六条文案与顺序不变，沿用原有六个 SVG 图形；文字组左右错位，但各组正文仍左对齐。
- 大标题上限 80px；桌面内容组最小高度 240px。它们是本屏参数，不是全站统一尺寸。
- 保留首屏底部露出第二屏、随后翻开，以及第三屏覆盖第二屏的过程。
- 正文始终可读，不等待透明淡入。连线随滚动向下绘制，当前阅读项与图形轻微联动。
- 使用未经过透视变换的布局坐标计算进度，向下滚动时不倒退；在第三屏进入视野前 64px 完成末段连线。
- 减少动态效果时完整显示静态连线；没有 JavaScript 时保留文字和图形。
- 透视距离随第二屏实际高度调整，保证倾斜面板不穿过镜头平面；保持原有翻转方向与滚动时间线。
- 当前人物条目没有新增点击跳转。抖音链接只是讨论过的可能性，尚未提供或确认具体地址。

### 3.6 交互表达与页尾

- 装饰性滚动联动与可点击操作应区分，不为没有去处的内容强行添加链接或手形光标。
- 保留现有其他页面，不继续为了“规范完整”主动重设计。
- 页尾允许以笔名作为视觉落款，不强制添加宣传口号或行动入口。

## 四、导航与页面关系

状态：用户于 2026-09-20 确认。

- 网站以完整首页承载个人展示。About、Work、Likes 点击后快速滚动到首页相应区块，沿用现有翻页与覆盖动效。
- Essays、Notes、文章和日记详情保留独立页面。在这些页面点击 About 或 Work，返回完整首页并定位到目标。
- About 要停在第二屏展开后可阅读的位置；不能停在倾斜半展开状态，也不能被第三屏盖住。
- 导航左上角在所有页面统一显示现有 Logo，不因进入文章页而退回文字“何必”。
- 旧的 About、Projects、Likes、Now 地址保留兼容跳转；Likes、Now 既有内容原样并入首页后部。
- 前四屏原有内容及顺序保持不变。跳转可以被用户的手动滚动或 Escape 中断；减少动态效果模式直接定位。
- 这次同时处理既有移动菜单的关闭与焦点行为，属于导航可用性，不代表开始移动端视觉重设计。
